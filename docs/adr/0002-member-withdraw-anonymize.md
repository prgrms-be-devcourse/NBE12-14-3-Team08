# 탈퇴한 회원은 지우지 않고 계정 정보만 익명화한다

회원 행을 물리 삭제하면 이 회원을 참조하는 방 멤버, 습관, 인증, 벌칙 기록의 관계가 깨지고 종료된 방의 결산과 통계가 틀어진다. 반대로 상태만 `WITHDRAWN`으로 두면 아이디와 구글 계정이 계속 점유되어 같은 아이디나 같은 구글 계정으로 다시 가입할 수 없고, 탈퇴한 뒤에도 계정을 가리키는 값이 남는다. 그래서 행은 남기되 `Member.withdraw()`가 사람을 가리키는 값(닉네임, 아이디, 비밀번호, 소셜 식별자)을 지정한 값으로 바꾼다.

| 컬럼 | 탈퇴 후 |
|---|---|
| `status` | `WITHDRAWN` |
| `nickname` | `탈퇴한 회원` |
| `username` | `withdrawn_{회원 id}` |
| `password` | `!withdrawn` (BCrypt 형식이 아니라 어떤 입력과도 일치하지 않음) |
| `provider` / `provider_id` | `LOCAL` / `NULL` |
| `refresh_token` | `NULL` |

닉네임은 사람을 가장 직접 가리키는 값이라 함께 바꾼다. 종료된 방의 멤버 목록·통계·정산에는 `탈퇴한 회원`으로 표시된다. 닉네임을 남기면 방 기록의 맥락은 유지되지만 익명화했다는 설명이 약해진다. 번호를 붙이면 구분은 되지만 목록이 길어져 고정 문구로 정했다. 인증 사진과 설명은 그대로 둔다.

## Consequences

- 탈퇴한 아이디와 구글 계정으로 다시 가입할 수 있다. 새 가입은 새 회원 id가 되어 이전 방·인증·벌칙 기록을 이어받지 않고, 이전 기록은 이전 회원(탈퇴 상태)에 남는다.
- 익명 아이디(`withdrawn_` + id)가 새 가입과 겹치지 않도록 `withdrawn_`로 시작하는 아이디는 가입할 수 없다. 겹치면 탈퇴할 때 유니크 제약에 걸려 탈퇴가 실패한다.
- 컬럼을 NULL로 비우지 않고 지정한 값으로 바꾼다. 아이디와 비밀번호가 `NOT NULL`이고 `ddl-auto: update`는 기존 DB의 제약을 풀어 주지 않아, NULL로 가려면 모든 환경의 DB를 직접 고쳐야 하기 때문이다.
- 이 정책 이전에 탈퇴한 회원은 한 번만 `docs/sql/anonymize-withdrawn-members.sql`을 실행해 같은 값으로 맞춘다.
- 인증 사진과 인증 설명(자유 입력)은 그대로 남아 개인을 알아볼 수 있는 정보(얼굴, 이름 등)가 있을 수 있다. 닉네임을 익명화해도 이 부분은 그대로라, 법적으로 더 엄격한 파기가 필요하면 별도 이슈에서 다룬다.
- 탈퇴한 회원이 여럿이면 목록과 통계에서 모두 같은 이름(`탈퇴한 회원`)으로 보인다. 수치와 순위는 그대로다.
