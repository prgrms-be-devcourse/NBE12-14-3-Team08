# Frontend Development Guide

본 프로젝트 프론트엔드(Next.js App Router)의 로컬 개발 환경 구축, 환경변수 관리 정책 및 구글 소셜 로그인 연동 명세입니다.

---

## 로컬 개발 환경 구동 (Getting Started)

패키지 매니저로 `npm`을 사용하며, 아래 명령어를 통해 의존성을 설치하고 로컬 개발 서버를 구동합니다.

```bash
cd frontend

# 1) 의존성 라이브러리 설치
npm install

# 2) 로컬 개발 서버 실행
npm run dev
```

* **개발 환경 주소:** 서버가 성공적으로 구동되면 브라우저에서 [http://localhost:3000](http://localhost:3000)으로 접속하여 프론트엔드 화면을 확인할 수 있습니다.
* **핫 리로딩(Hot Reloading):** `src/app/` 디렉터리 내의 컴포넌트 및 페이지 코드를 수정하면 브라우저 새로고침 없이 변경 사항이 실시간으로 반영됩니다.

---

## 환경변수 및 보안 관리 정책 (Environment Variables)

프로젝트 보안과 API 격리를 위해 브라우저 노출용 키와 백엔드 시크릿 키를 엄격히 분리하여 관리합니다.

### 1. 클라이언트 및 백엔드 키 분리 구조
* **Frontend (`frontend/.env.local`):** 브라우저단에 공개되어 구글 로그인 렌더링에 사용되는 클라이언트 ID 키를 관리합니다.
  ```env
  NEXT_PUBLIC_GOOGLE_CLIENT_ID=://googleusercontent.com
  ```
* **Backend:** 소셜 인증 토큰 검증 및 인가 처리에 필요한 시크릿 키는 백엔드 인프라의 환경변수(`GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`)로 주입받아 처리합니다.

> ⚠️ **보안 주의사항:** 팀 내부적으로 공유된 실서비스/테스트용 시크릿 키와 크레덴셜 정보는 **절대로 Git 저장소에 커밋하거나 퍼블릭에 노출하지 않습니다.** `.env.local` 파일은 프로젝트 최상위 `.gitignore`에 의해 추적 대상에서 완전히 제외됩니다.

## 구글 소셜 로그인 연동 가이드 (OAuth2 Authentication)

본 프로젝트는 사용자 경험 향상을 위해 자체 로그인 외에 구글 OAuth2 소셜 로그인을 지원합니다.

### 1. UI 렌더링 조건 및 폴백(Fallback) 메커니즘
* 프론트엔드 애플리케이션은 로드 시 `NEXT_PUBLIC_GOOGLE_CLIENT_ID` 환경변수의 주입 여부를 동적으로 확인합니다.
* **클라이언트 ID가 설정된 경우:** 소셜 로그인 UI 콤포넌트가 활성화되며 구글 로그인 인증 흐름을 진행할 수 있습니다.
* **클라이언트 ID가 미설정된 경우 (폴백):** 버튼이 화면에 나타나지 않으며, 서비스 이용에 차질이 없도록 기본 아이디/비밀번호 인증 폼으로만 로그인을 진행할 수 있게 안전한 폴백 아키텍처가 동작합니다.

### 2. 가이드 및 트러블슈팅 레퍼런스
구글 개발자 콘솔(Google Cloud Console)에서 OAuth 클라이언트 ID를 발급받는 구체적인 방법, 리다이렉트 URI 설정 규칙, 그리고 소셜 로그인 연동 과정에서 발생하는 다양한 에러 핸들링은 아래 문서를 참고해 주세요.
